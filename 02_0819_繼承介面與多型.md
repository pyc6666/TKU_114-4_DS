# 8/19 教材：繼承、介面與多型

## 單元名稱

Inheritance、method overriding、abstract class、interface 與 polymorphism

## 課程定位

前一單元使用 encapsulation 與 composition 分配物件責任。本單元處理「多種物件具有共同操作，但實作方式不同」的問題。Java Collections Framework 大量使用 interface 與 polymorphism，例如變數型態可以宣告為 `List<String>`，實際物件則可能是 `ArrayList<String>` 或 `LinkedList<String>`。

## 學習目標

完成本單元後，應能：

1. 分辨 is-a 與 has-a 關係。
2. 使用 `extends` 與 `super` 建立合理的繼承階層。
3. 使用 `@Override` 改寫繼承方法。
4. 透過父類別 reference 操作不同子類別物件。
5. 建立 abstract class 與 abstract method。
6. 定義並實作 interface。
7. 根據共享狀態與共享行為選擇 abstract class、interface 或 composition。

## 先備知識

- Class、object、constructor、encapsulation。
- Object reference 與 composition。
- 陣列、enhanced `for` loop。
- 建立 `0819` 資料夾，所有範例依標示檔名存放。

## 問題情境

付款系統可能同時支援信用卡、電子錢包與轉帳。三種付款方式都有 `pay(amount)`，但驗證及處理方式不同。如果主程式為每種付款方式分別寫一套 `if`，新增付款方式時就必須修改多處程式。

利用 interface 與 polymorphism，主程式只依賴共同的 `PaymentMethod` 操作。新增付款方式時，只要增加新的實作 class，原本的結帳流程不必跟著重寫。

## 核心概念

### 概念 1：Inheritance 表達 is-a 關係

#### 概念說明

Inheritance 讓 subclass 繼承 superclass 可存取的 field 與 method。語法使用 `extends`：

```java
class Employee { }
class FullTimeEmployee extends Employee { }
```

這個關係應能合理讀成「FullTimeEmployee is an Employee」。若只能讀成「擁有」或「使用」，通常應改用 composition。

Java class 只能直接繼承一個 superclass。所有沒有明確指定父類別的 class，最後都繼承自 `Object`。

#### 實際應用

- `FullTimeEmployee` 與 `PartTimeEmployee` 都是 `Employee`。
- `ArrayList` 與 `LinkedList` 都是 `List` 的實作，但此處是 interface implementation。
- 不同 Tree node 若只有資料型態不同，通常用 generic，不一定需要 inheritance。

#### 資料變化

Subclass 物件包含 superclass 定義的部分，也包含自己的新增部分：

```text
FullTimeEmployee object
├── Employee: id, name
└── FullTimeEmployee: monthlySalary
```

#### 何時適合使用

Subclass 確實是 superclass 的一種，而且所有繼承行為都合理時才使用。只是為了重用幾行程式，不足以構成良好 inheritance。

#### 範例程式

檔名：`InheritanceBasics.java`

```java
class Employee {
    private String id;
    private String name;

    Employee(String id, String name) {
        this.id = id;
        this.name = name;
    }

    String label() {
        return id + " " + name;
    }
}

class FullTimeEmployee extends Employee {
    private int monthlySalary;

    FullTimeEmployee(String id, String name, int monthlySalary) {
        super(id, name);
        this.monthlySalary = Math.max(0, monthlySalary);
    }

    int annualSalary() {
        return monthlySalary * 12;
    }
}

public class InheritanceBasics {
    public static void main(String[] args) {
        FullTimeEmployee employee =
            new FullTimeEmployee("E101", "Amy", 50000);

        System.out.println(employee.label());
        System.out.println("年薪：" + employee.annualSalary());
    }
}
```

執行結果：

```text
E101 Amy
年薪：600000
```

#### 執行重點

`super(id, name)` 必須在 subclass constructor 的第一個敘述中呼叫 superclass constructor。

### 概念 2：Method overriding 與 @Override

#### 概念說明

Subclass 可以重新提供 superclass instance method 的實作，稱為 method overriding。Method 名稱、參數型態與順序必須相同，回傳型態也必須相容。

`@Override` 會要求編譯器檢查是否真的改寫既有 method。若 method 名稱拼錯或參數不同，編譯器會立即指出，而不是默默建立另一個 overload。

#### 實際應用

- 不同員工使用不同薪資計算方式。
- 不同圖形實作各自的 `area()`。
- 不同資料輸出格式改寫 `toString()`。

#### 資料變化

```text
employee.calculatePay()
實際物件是 FullTimeEmployee -> 執行 FullTimeEmployee.calculatePay()
實際物件是 HourlyEmployee   -> 執行 HourlyEmployee.calculatePay()
```

#### 何時適合使用

共同操作的語意一致，但子類別需要不同實作時使用 overriding。若子類別根本不應該擁有該操作，代表繼承階層可能設計錯誤。

#### 範例程式

檔名：`OverridePayDemo.java`

```java
class PayEmployee {
    private String name;

    PayEmployee(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    int calculatePay() {
        return 0;
    }
}

class MonthlyEmployee extends PayEmployee {
    private int salary;

    MonthlyEmployee(String name, int salary) {
        super(name);
        this.salary = salary;
    }

    @Override
    int calculatePay() {
        return salary;
    }
}

class HourlyEmployee extends PayEmployee {
    private int hours;
    private int hourlyRate;

    HourlyEmployee(String name, int hours, int hourlyRate) {
        super(name);
        this.hours = hours;
        this.hourlyRate = hourlyRate;
    }

    @Override
    int calculatePay() {
        return hours * hourlyRate;
    }
}

public class OverridePayDemo {
    public static void main(String[] args) {
        MonthlyEmployee amy = new MonthlyEmployee("Amy", 50000);
        HourlyEmployee ben = new HourlyEmployee("Ben", 80, 220);

        System.out.println(amy.getName() + "：" + amy.calculatePay());
        System.out.println(ben.getName() + "：" + ben.calculatePay());
    }
}
```

執行結果：

```text
Amy：50000
Ben：17600
```

#### 執行重點

刪除或拼錯 `@Override` 下方 method 的名稱，觀察編譯器如何協助發現錯誤。

### 概念 3：Polymorphism 與 dynamic dispatch

#### 概念說明

父型態 reference 可以指向任何合法子型態物件：

```java
PayEmployee employee = new MonthlyEmployee("Amy", 50000);
```

編譯器根據 reference type 決定可以呼叫哪些 method；執行時則根據實際 object type 選擇 overridden method，這稱為 dynamic dispatch。

這讓主程式可以用同一段迴圈處理不同子類別，不必為每一種類型重複流程。

#### 實際應用

- 用 `Employee[]` 保存不同員工。
- 用 `List` reference 切換 `ArrayList` 與 `LinkedList`。
- 用共同 interface 管理不同付款、通知或儲存策略。

#### 資料變化

陣列元素保存不同 object reference，但每次呼叫都使用相同 method：

```text
employees[0] -> MonthlyEmployee -> calculatePay() = 50000
employees[1] -> HourlyEmployee  -> calculatePay() = 17600
```

#### 何時適合使用

流程相同、實作不同，且未來可能加入新類型時，polymorphism 可以降低主流程對具體 class 的依賴。

#### 範例程式

檔名：`PolymorphismArrayDemo.java`

```java
abstract class Shape {
    private String name;

    Shape(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    abstract double area();
}

class RectangleShape extends Shape {
    private double width;
    private double height;

    RectangleShape(double width, double height) {
        super("Rectangle");
        this.width = width;
        this.height = height;
    }

    @Override
    double area() {
        return width * height;
    }
}

class CircleShape extends Shape {
    private double radius;

    CircleShape(double radius) {
        super("Circle");
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}

public class PolymorphismArrayDemo {
    public static void main(String[] args) {
        Shape[] shapes = {
            new RectangleShape(4, 5),
            new CircleShape(3)
        };

        for (Shape shape : shapes) {
            System.out.printf("%s area=%.2f%n",
                shape.getName(), shape.area());
        }
    }
}
```

執行結果：

```text
Rectangle area=20.00
Circle area=28.27
```

#### 執行重點

迴圈變數型態是 `Shape`，但 `area()` 會依實際物件執行不同版本。

### 概念 4：Abstract class 定義共同骨架

#### 概念說明

Abstract class 不能直接 `new`，但可以保存 field、constructor、一般 method 與 abstract method。Abstract method 只有宣告，沒有 method body，要求非 abstract subclass 必須提供實作。

Abstract class 適合一群關係緊密的 class：它們共享狀態與部分實作，但某些操作必須由 subclass 決定。

#### 實際應用

- 不同報表共享標題與建立日期，但內容產生方式不同。
- 不同帳戶共享帳號與餘額，但費用計算不同。
- 不同 tree traversal 共享 tree，但走訪策略不同。

#### 資料變化

Abstract superclass 先完成共同驗證，subclass 只處理差異：

```text
Notification.send()
├── validateMessage() 共同處理
└── deliver() 由 Email / SMS 各自實作
```

#### 何時適合使用

需要共享 instance state、constructor 或 protected helper method 時使用 abstract class。只需要規定可執行哪些操作，而不需要共享狀態時，通常使用 interface。

#### 範例程式

檔名：`AbstractNotificationDemo.java`

```java
abstract class Notification {
    private String receiver;

    Notification(String receiver) {
        this.receiver = receiver;
    }

    final void send(String message) {
        if (message == null || message.isBlank()) {
            System.out.println("訊息不可為空");
            return;
        }
        deliver(receiver, message);
    }

    protected abstract void deliver(String receiver, String message);
}

class EmailNotification extends Notification {
    EmailNotification(String receiver) {
        super(receiver);
    }

    @Override
    protected void deliver(String receiver, String message) {
        System.out.println("EMAIL to " + receiver + "：" + message);
    }
}

class SmsNotification extends Notification {
    SmsNotification(String receiver) {
        super(receiver);
    }

    @Override
    protected void deliver(String receiver, String message) {
        System.out.println("SMS to " + receiver + "：" + message);
    }
}

public class AbstractNotificationDemo {
    public static void main(String[] args) {
        Notification email = new EmailNotification("amy@example.com");
        Notification sms = new SmsNotification("0912345678");

        email.send("Assignment uploaded");
        sms.send("Class starts at 10:10");
        sms.send("   ");
    }
}
```

執行結果：

```text
EMAIL to amy@example.com：Assignment uploaded
SMS to 0912345678：Class starts at 10:10
訊息不可為空
```

#### 執行重點

`send()` 被宣告為 `final`，確保所有 subclass 都會執行共同驗證；只有 `deliver()` 由 subclass 決定。

### 概念 5：Interface 定義可替換的行為契約

#### 概念說明

Interface 定義實作 class 必須提供的行為。Class 使用 `implements` 實作 interface，並提供其 abstract method 的 public 實作。

一個 class 可以實作多個 interface，因此 interface 適合描述能力，例如 `Comparable`、`Runnable`、`Payable`，而不是固定的家族階層。

#### 實際應用

- 付款方式都實作 `PaymentMethod`。
- 可匯出的報表都實作 `Exportable`。
- Java Collections 中 `ArrayList` 與 `LinkedList` 都實作 `List`。

#### 資料變化

Checkout 只接收 `PaymentMethod`：

```text
checkout(card, 1200)   -> CardPayment.pay(1200)
checkout(wallet, 500) -> WalletPayment.pay(500)
```

#### 何時適合使用

希望多個可能互不相關的 class 提供相同行為，並讓呼叫端不依賴具體 class 時使用 interface。

#### 範例程式

檔名：`PaymentInterfaceDemo.java`

```java
interface PaymentMethod {
    boolean pay(int amount);
    String getName();
}

class CardPayment implements PaymentMethod {
    private int limit;

    CardPayment(int limit) {
        this.limit = limit;
    }

    @Override
    public boolean pay(int amount) {
        return amount > 0 && amount <= limit;
    }

    @Override
    public String getName() {
        return "Card";
    }
}

class WalletPayment implements PaymentMethod {
    private int balance;

    WalletPayment(int balance) {
        this.balance = balance;
    }

    @Override
    public boolean pay(int amount) {
        if (amount <= 0 || amount > balance) {
            return false;
        }
        balance -= amount;
        return true;
    }

    @Override
    public String getName() {
        return "Wallet";
    }
}

public class PaymentInterfaceDemo {
    static void checkout(PaymentMethod method, int amount) {
        System.out.println(method.getName() + " pay " + amount + "：" +
            method.pay(amount));
    }

    public static void main(String[] args) {
        PaymentMethod card = new CardPayment(3000);
        PaymentMethod wallet = new WalletPayment(800);

        checkout(card, 1200);
        checkout(wallet, 500);
        checkout(wallet, 500);
    }
}
```

執行結果：

```text
Card pay 1200：true
Wallet pay 500：true
Wallet pay 500：false
```

#### 執行重點

`checkout()` 不知道實際付款 class，只依賴 `PaymentMethod` 契約。

### 概念 6：一個 class 可以實作多個 interface

#### 概念說明

Java 不允許一個 class 同時 `extends` 多個 class，但允許實作多個 interface。這稱為 multiple inheritance of type，讓同一物件可以具備多種獨立能力。

```java
class Report implements Printable, Exportable
```

Interface 應保持責任集中。若一個 interface 包含太多互不相關的方法，實作 class 會被迫提供不需要的操作。

#### 實際應用

- 報表同時可以列印與匯出。
- 工作項目同時可以比較優先順序與顯示摘要。
- Graph 可以同時支援走訪與路徑搜尋能力。

#### 資料變化

同一個 `SystemReport` object 可以分別被視為 `Printable` 或 `Exportable` reference，呼叫不同能力。

#### 何時適合使用

多個能力彼此獨立，而且 class 確實需要同時提供時使用。不要建立只為了放常數、沒有清楚行為的 interface。

#### 範例程式

檔名：`MultipleInterfaceDemo.java`

```java
interface Printable {
    void print();
}

interface Exportable {
    String export();
}

class SystemReport implements Printable, Exportable {
    private String title;
    private int recordCount;

    SystemReport(String title, int recordCount) {
        this.title = title;
        this.recordCount = recordCount;
    }

    @Override
    public void print() {
        System.out.println(title + " records=" + recordCount);
    }

    @Override
    public String export() {
        return title + "," + recordCount;
    }
}

public class MultipleInterfaceDemo {
    public static void main(String[] args) {
        SystemReport report = new SystemReport("Inventory", 42);

        Printable printable = report;
        Exportable exportable = report;

        printable.print();
        System.out.println(exportable.export());
    }
}
```

執行結果：

```text
Inventory records=42
Inventory,42
```

#### 執行重點

兩個 reference 指向同一個 `SystemReport` object，但各自只看得到所屬 interface 宣告的 method。

### 概念 7：Abstract class、interface 與 composition 的選擇

#### 概念說明

三種設計方式解決的問題不同：

| 設計方式 | 主要關係 | 適合情況 |
|---|---|---|
| Abstract class | is-a | 關係緊密、需要共享 state 與部分實作 |
| Interface | can-do | 需要共同契約與可替換實作，不要求共享 state |
| Composition | has-a | 一個物件包含或使用另一個物件 |

可以同時使用三者。例如 `CheckoutService` has a `PaymentMethod`，`PaymentMethod` 是 interface，實際 object 可能是 `CardPayment` 或 `WalletPayment`。

#### 實際應用

Java Collections Framework 將 interface 與 implementation 分開。呼叫端使用 `List`，實際選擇 `ArrayList` 或 `LinkedList`，正是 interface-based polymorphism。

#### 資料變化

```text
PriceCalculator -> DiscountPolicy reference -> NoDiscount object
PriceCalculator -> DiscountPolicy reference -> PercentageDiscount object
```

Calculator 的 class 不變，只要換入不同 policy object，計算結果就可以改變。

#### 何時適合使用

先描述真實關係，再選語法。不要先決定一定要使用 inheritance，才硬把 class 塞進父子關係。

#### 範例程式

檔名：`StrategyCompositionDemo.java`

```java
interface DiscountPolicy {
    int apply(int originalPrice);
}

class NoDiscount implements DiscountPolicy {
    @Override
    public int apply(int originalPrice) {
        return originalPrice;
    }
}

class PercentageDiscount implements DiscountPolicy {
    private int percent;

    PercentageDiscount(int percent) {
        this.percent = Math.max(0, Math.min(100, percent));
    }

    @Override
    public int apply(int originalPrice) {
        return originalPrice * (100 - percent) / 100;
    }
}

class PriceCalculator {
    private DiscountPolicy policy;

    PriceCalculator(DiscountPolicy policy) {
        this.policy = policy;
    }

    int calculate(int originalPrice) {
        return policy.apply(Math.max(0, originalPrice));
    }
}

public class StrategyCompositionDemo {
    public static void main(String[] args) {
        PriceCalculator regular = new PriceCalculator(new NoDiscount());
        PriceCalculator sale =
            new PriceCalculator(new PercentageDiscount(20));

        System.out.println("原價：" + regular.calculate(1000));
        System.out.println("八折：" + sale.calculate(1000));
    }
}
```

執行結果：

```text
原價：1000
八折：800
```

#### 執行重點

`PriceCalculator` 沒有繼承折扣 class，而是透過 composition 保存 `DiscountPolicy`，可以在建立時替換策略。

### 概念 8：`super` 與 constructor chain

#### 概念說明

建立 subclass object 時，必須先完成 superclass 的部分，再完成 subclass 自己的部分。Subclass constructor 可以使用 `super(...)` 指定要呼叫的 superclass constructor。

如果沒有寫 `super(...)`，compiler 會嘗試在第一行加入 `super()`。當 superclass 沒有無參數 constructor，subclass 就必須明確呼叫現有的 constructor。

`super(...)` 和 `this(...)` 都必須放在 constructor 第一行，且不能在同一個 constructor 中同時使用兩者。

#### 實際應用

- 員工 superclass 統一驗證 id 與 name。
- 商品 superclass 建立共同編號與價格。
- UI component superclass 先建立位置與大小，subclass 再加入特殊屬性。

#### 資料變化

```text
new SalariedWorker("E01", "Amy", 50000)
  -> Worker constructor
  -> SalariedWorker constructor
  -> object 建立完成
```

#### 設計判斷

Superclass constructor 應該只處理 superclass 負責的狀態。Subclass 不能直接依賴 superclass 的 private field，而是透過 constructor、`protected` 或具有明確意義的 method 合作。不應為了讓 subclass 方便而把所有 field 都改成 `protected`。

#### 範例程式

檔名：`ConstructorChainDemo.java`

```java
abstract class Worker {
    private final String id;
    private final String name;

    Worker(String id, String name) {
        this.id = id;
        this.name = name;
        System.out.println("Worker constructor: " + id);
    }

    String label() {
        return id + " " + name;
    }

    abstract int monthlyPay();
}

class SalariedWorker extends Worker {
    private final int salary;

    SalariedWorker(String id, String name, int salary) {
        super(id, name);
        this.salary = Math.max(0, salary);
        System.out.println("SalariedWorker constructor: " + salary);
    }

    @Override
    int monthlyPay() {
        return salary;
    }
}

public class ConstructorChainDemo {
    public static void main(String[] args) {
        Worker worker = new SalariedWorker("E01", "Amy", 50000);
        System.out.println(worker.label() + " pay=" + worker.monthlyPay());
    }
}
```

執行結果：

```text
Worker constructor: E01
SalariedWorker constructor: 50000
E01 Amy pay=50000
```

#### 實作變化

新增 `HourlyWorker`，constructor 接收 id、name、hourlyRate 與 hours，必須先呼叫 `super(id, name)`，再完成 subclass field 驗證。

### 概念 9：Upcasting、downcasting 與 `instanceof`

#### 概念說明

Upcasting 是將 subclass object 當作 superclass 或 interface 使用，例如 `Media media = new Video()`。這是安全且常見的操作，不需要明確 cast。

Downcasting 是將較一般的 reference type 轉回較具體的 subclass type。如果 object 實際不是該 subclass，會發生 `ClassCastException`。Java 17 可以使用 pattern matching for `instanceof`：

```java
if (media instanceof Video video) {
    video.changeResolution("4K");
}
```

這會同時檢查型態並建立安全的 `video` reference。

#### 實際應用

- 統一處理多種事件，少數情況需要使用特殊資訊。
- 外部 API 回傳共同型態，呼叫端必須判斷具體型態。
- 除錯時觀察 reference type 和 object type 的差異。

#### 資料變化

| Expression | Reference type | Object type | 可呼叫的特殊 method |
|---|---|---|---|
| `Media media = new Video(...)` | `Media` | `Video` | 不可直接呼叫 Video-only method |
| `media instanceof Video video` 成功 | `Video` | `Video` | 可以 |

#### 設計判斷

如果主要流程充滿 `instanceof`，通常代表共同行為沒有正確放進 superclass 或 interface。Downcasting 應該用於少數真正的 subclass-specific operation，不是取代 polymorphism。

#### 範例程式

檔名：`SafeCastingDemo.java`

```java
abstract class MediaAsset {
    private final String title;

    MediaAsset(String title) {
        this.title = title;
    }

    String getTitle() {
        return title;
    }

    abstract void play();
}

class VideoAsset extends MediaAsset {
    private String resolution;

    VideoAsset(String title, String resolution) {
        super(title);
        this.resolution = resolution;
    }

    @Override
    void play() {
        System.out.println("Play video: " + getTitle() + " " + resolution);
    }

    void changeResolution(String resolution) {
        this.resolution = resolution;
    }
}

class AudioAsset extends MediaAsset {
    AudioAsset(String title) {
        super(title);
    }

    @Override
    void play() {
        System.out.println("Play audio: " + getTitle());
    }
}

public class SafeCastingDemo {
    static void prepare(MediaAsset asset) {
        if (asset instanceof VideoAsset video) {
            video.changeResolution("1080p");
        }
        asset.play();
    }

    public static void main(String[] args) {
        prepare(new VideoAsset("Tree Tutorial", "720p"));
        prepare(new AudioAsset("Queue Podcast"));
    }
}
```

執行結果：

```text
Play video: Tree Tutorial 1080p
Play audio: Queue Podcast
```

#### 執行重點

`prepare` 對所有 media 都呼叫 polymorphic `play()`，只有解析度設定是 Video-specific operation。

### 概念 10：Interface default method

#### 概念說明

Interface 可以使用 `default` 提供有 method body 的預設實作。它的重要用途是：在已有多個 implementation 的 interface 中新增行為時，提供共通做法，不需要立即修改所有 class。

Implementation class 可以 override default method。當一個 class 實作兩個 interface，而兩個 interface 有相同簽章的 default method，class 必須自己 override 來解決衝突。

#### 實際應用

- 所有通知管道共用的格式檢查。
- 已發佈 API 新增可選功能。
- 在不共用 state 的情況下提供小型共用邏輯。

#### 資料變化

```text
EmailAlert.send(...)
  -> 使用 interface default isValid(...)
  -> 加上 EmailAlert 自己的 email 格式檢查
```

#### 設計判斷

Default method 不應該承擔需要大量 field 或複雜 workflow 的邏輯。如果需要共享狀態，abstract class 或 composition service 通常更清楚。

#### 範例程式

檔名：`DefaultMethodDemo.java`

```java
interface AlertChannel {
    boolean send(String receiver, String message);

    default boolean isValid(String receiver, String message) {
        return receiver != null && !receiver.isBlank()
                && message != null && !message.isBlank();
    }
}

class EmailAlert implements AlertChannel {
    @Override
    public boolean send(String receiver, String message) {
        if (!isValid(receiver, message) || !receiver.contains("@")) {
            return false;
        }
        System.out.println("EMAIL to " + receiver + ": " + message);
        return true;
    }
}

class ConsoleAlert implements AlertChannel {
    @Override
    public boolean send(String receiver, String message) {
        if (!isValid(receiver, message)) {
            return false;
        }
        System.out.println("CONSOLE " + receiver + ": " + message);
        return true;
    }
}

public class DefaultMethodDemo {
    public static void main(String[] args) {
        AlertChannel email = new EmailAlert();
        AlertChannel console = new ConsoleAlert();

        System.out.println(email.send("amy@example.com", "Class starts"));
        System.out.println(console.send("B113", "Class starts"));
        System.out.println(email.send("invalid", "Class starts"));
    }
}
```

執行結果：

```text
EMAIL to amy@example.com: Class starts
true
CONSOLE B113: Class starts
true
false
```

#### 實作變化

在 interface 新增 `default String preview(String message)`，超過 10 個字元時只回傳前 10 個字元加上 `...`。

### 概念 11：Polymorphic parameter 與 return type

#### 概念說明

Polymorphism 不只用在陣列。Method parameter 使用 interface 或 superclass，可以接收任何 implementation；method return type 使用共同型態，可以根據設定回傳不同具體物件。

這種做法可將「如何選擇 object」與「如何使用 object」分開。使用端只知道 interface contract，不需要知道具體 class。

#### 實際應用

- Factory method 依設定建立付款方式或通知管道。
- Service method 接收可替換 strategy。
- Unit testing 傳入測試 implementation，不需要修改主流程。

#### 資料變化

```text
create("member") -> MemberFeePolicy object
calculate(policy, 1000) -> 只依賴 FeePolicy
```

#### 設計判斷

Parameter 與 return type 應該選擇使用端真正需要的最小共同型態。如果 caller 只需要 `calculate()`，就回傳 `FeePolicy`，不要暴露具體 `MemberFee`。但如果後續必須呼叫 subclass-only method，就要重新檢查 interface 是否少了應有行為。

#### 範例程式

檔名：`PolymorphicFactoryDemo.java`

```java
interface FeePolicy {
    int calculate(int amount);
    String name();
}

class RegularFee implements FeePolicy {
    @Override
    public int calculate(int amount) {
        return Math.max(0, amount);
    }

    @Override
    public String name() {
        return "regular";
    }
}

class MemberFee implements FeePolicy {
    @Override
    public int calculate(int amount) {
        return Math.max(0, amount) * 90 / 100;
    }

    @Override
    public String name() {
        return "member";
    }
}

public class PolymorphicFactoryDemo {
    static FeePolicy createPolicy(String type) {
        if ("member".equalsIgnoreCase(type)) {
            return new MemberFee();
        }
        return new RegularFee();
    }

    static void printFee(FeePolicy policy, int amount) {
        System.out.println(policy.name() + " fee=" + policy.calculate(amount));
    }

    public static void main(String[] args) {
        FeePolicy first = createPolicy("member");
        FeePolicy second = createPolicy("unknown");
        printFee(first, 1000);
        printFee(second, 1000);
    }
}
```

執行結果：

```text
member fee=900
regular fee=1000
```

#### 執行重點

`createPolicy` 的 return type 是 `FeePolicy`，但實際可回傳任何實作該 interface 的 object。

### 概念 12：綜合應用，多管道通知與費用計算

#### 問題情境

訂單完成時要根據會員類型計算金額，再透過可替換的 channel 發送通知。費用規則與通知方式都可能獨立變化，因此 `CheckoutService` 使用兩個 interface 作為 composition component。

#### 實際應用

- 電商結帳依會員、活動或地區選擇計價策略。
- 依帳號偏好選擇 Email、SMS 或 App notification。
- 測試時使用簡單 channel 取代真實外部服務。

#### 設計分工

- `PricingPolicy`：負責計算實付金額。
- `NotificationChannel`：負責發送訊息。
- `CheckoutService`：協調結帳流程，不實作具體折扣與傳送技術。

#### 資料變化

| Pricing object | Channel object | 原價 | 實付 | 通知結果 |
|---|---|---:|---:|---|
| `VipPricing` | `EmailChannel` | 2000 | 1700 | receiver 合法時成功 |
| `StandardPricing` | `ConsoleChannel` | 800 | 800 | 成功 |

#### 設計判斷

計價和通知是兩個獨立變化軸，使用 composition 可自由組合，不需要建立 `VipEmailCheckout`、`VipConsoleCheckout` 等大量 subclass。如果所有策略都必須共享大量 state，才需要重新評估 abstract class。

#### 範例程式

檔名：`CheckoutNotificationSystem.java`

```java
interface PricingPolicy {
    int finalPrice(int originalPrice);
}

class StandardPricing implements PricingPolicy {
    @Override
    public int finalPrice(int originalPrice) {
        return Math.max(0, originalPrice);
    }
}

class VipPricing implements PricingPolicy {
    @Override
    public int finalPrice(int originalPrice) {
        return Math.max(0, originalPrice) * 85 / 100;
    }
}

interface NotificationChannel {
    boolean send(String receiver, String message);
}

class EmailChannel implements NotificationChannel {
    @Override
    public boolean send(String receiver, String message) {
        if (receiver == null || !receiver.contains("@")) {
            return false;
        }
        System.out.println("EMAIL " + receiver + " -> " + message);
        return true;
    }
}

class ConsoleChannel implements NotificationChannel {
    @Override
    public boolean send(String receiver, String message) {
        System.out.println("CONSOLE " + receiver + " -> " + message);
        return true;
    }
}

class CheckoutService {
    private final PricingPolicy pricing;
    private final NotificationChannel channel;

    CheckoutService(PricingPolicy pricing, NotificationChannel channel) {
        this.pricing = pricing;
        this.channel = channel;
    }

    boolean checkout(String orderId, int originalPrice, String receiver) {
        if (orderId == null || orderId.isBlank() || originalPrice < 0) {
            return false;
        }
        int amount = pricing.finalPrice(originalPrice);
        return channel.send(receiver,
                "order=" + orderId + ", amount=" + amount);
    }
}

public class CheckoutNotificationSystem {
    public static void main(String[] args) {
        CheckoutService vipEmail = new CheckoutService(
                new VipPricing(), new EmailChannel());
        CheckoutService regularConsole = new CheckoutService(
                new StandardPricing(), new ConsoleChannel());

        System.out.println("sent="
                + vipEmail.checkout("O100", 2000, "amy@example.com"));
        System.out.println("sent="
                + regularConsole.checkout("O101", 800, "counter"));
        System.out.println("sent="
                + vipEmail.checkout("O102", 500, "invalid"));
    }
}
```

執行結果：

```text
EMAIL amy@example.com -> order=O100, amount=1700
sent=true
CONSOLE counter -> order=O101, amount=800
sent=true
sent=false
```

#### 實作變化

新增 `StudentPricing` 九折與 `SmsChannel`。不可修改 `CheckoutService.checkout()` 的 method body，只能透過新的 implementation 擴充功能。

## 程式執行追蹤

### 追蹤一：Constructor chain

| 步驟 | 執行位置 | 已設定狀態 |
|---|---|---|
| 1 | `new SalariedWorker(...)` | 配置物件空間 |
| 2 | `Worker` constructor | id、name |
| 3 | `SalariedWorker` constructor | salary |
| 4 | constructor 結束 | 可安全使用完整物件 |

### 追蹤二：Dynamic dispatch

```java
FeePolicy policy = new MemberFee();
int result = policy.calculate(1000);
```

1. Compiler 根據 `FeePolicy` 確認 `calculate(int)` 存在。
2. Runtime 根據 object type `MemberFee` 選擇 overridden method。
3. 執行 `MemberFee.calculate(1000)`，得到 900。

## 除錯練習

### 除錯練習一：Superclass 沒有無參數 constructor

```java
class Parent {
    Parent(String id) { }
}

class Child extends Parent {
    Child() { }
}
```

原因：`Child()` 會隱含嘗試 `super()`，但 `Parent` 只有 `Parent(String)`。

修正：

```java
Child() {
    super("UNKNOWN");
}
```

### 除錯練習二：不安全 downcasting

```java
MediaAsset asset = new AudioAsset("Podcast");
VideoAsset video = (VideoAsset) asset;
```

這段可以編譯，但 runtime 會發生 `ClassCastException`。必須先使用 `instanceof VideoAsset`。更重要的是先判斷這個功能是否應該放進共同 interface，減少 downcast。

## 常見錯誤與診斷

| 問題 | 常見原因 | 修正方式 |
|---|---|---|
| `Implicit super constructor ... is undefined` | Superclass 沒有無參數 constructor | 在 subclass constructor 第一行呼叫正確 `super(...)` |
| `method does not override` | Method 名稱、參數或存取權不同 | 對照 superclass/interface 宣告，保留 `@Override` |
| Interface method 實作失敗 | 實作 method 不是 `public` | Interface abstract method 的實作必須是 public |
| 父型態 reference 看不到 subclass method | 編譯器依 reference type 判斷可見 method | 將共同操作放入父型態，不濫用 downcast |
| 建立 abstract class 物件失敗 | Abstract class 不能直接 `new` | 建立具體 subclass 物件 |
| 子類別出現不合理空方法 | Inheritance 關係不成立或 interface 太大 | 重設 class 關係或拆分 interface |

## 評分規準

| 評分項目 | 完整達成 | 部分達成 | 尚未達成 |
|---|---|---|---|
| Inheritance 關係 | Is-a 合理且 superclass 責任清楚 | 可執行但階層勉強 | 只為重用程式而錯誤繼承 |
| Overriding | 正確使用 `@Override` 並呈現差異 | 部分 subclass 完成 | Method 簽章錯誤或未覆寫 |
| Polymorphism | 主流程只依賴共同型態 | 仍有少量型態判斷 | 每種 class 都寫一套流程 |
| Interface/abstract | 能依共享 state 與 behavior 正確選擇 | 結果正確但選擇理由不清 | Interface 或 abstract class 無法編譯 |
| 邊界處理 | Null、空白與不合法值均處理 | 僅處理一般案例 | 不合法資料造成錯誤狀態 |
| GitHub 繳交 | `0819` 連結及檔案完整 | 紀錄或命名有缺漏 | 未 push 或連結錯誤 |
